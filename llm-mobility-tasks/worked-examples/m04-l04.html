Instructing the assistant to draft only from supplied material — worked example

After working through this example you will be able to

  • Write a grounding instruction that names a source document, forbids outside knowledge and inference, and requires an explicit 'not available' response when the source is silent on a point.
  • Apply that instruction to a real Horizon Europe call text before drafting a briefing paragraph from it.
  • Check a drafted paragraph clause by clause against a source document and produce a verification table recording a supported/not-supported verdict for every factual claim.
  • Identify which claims in an ungrounded draft were fabricated and explain why a grounding instruction would have forced them to 'not available' instead.

The previous lecture ended by promising exactly this next step: paste a real call text, write a grounding instruction from the template, draft a section, and check every figure, name and commitment against the source material. That is the exercise here.

You work in the mobility unit of a local authority. Your manager has asked for a short briefing paragraph on a Horizon Europe call your department is considering — HORIZON-CL5-2023-D6-01-06, on zero-emission e-commerce and freight delivery — specifically what the call requires from local authorities as partners.

A colleague already tried this with an assistant using a soft instruction — 'please summarise what this call wants from local authorities using the text I've pasted' — and the result reads fluently, but there is no way to tell at a glance whether every figure, name and commitment in it actually appears in the call text. That draft needs to be checked clause by clause before anything from it reaches an official document.

Colleague's draft paragraph: 'This topic requires local authorities to act as full beneficiaries and formal signatories of the grant agreement, not just associated partners. Proposals must include an intersectional consumer-behaviour analysis and must build a toolset developed with and for local authorities. Projects are also expected to cooperate with the CIVITAS network of cities, and local authorities are required to co-fund at least 10% of the project budget from municipal sources.'

Step 1 — Read the call text itself

Before writing anything, the call text at CORDIS was opened directly and read for the three points the manager's brief turns on: the role required of local authorities, any named consumer-behaviour analysis requirement, and any reference to the CIVITAS network.[1]

Test with selected retailers and representative customers, and in collaboration with relevant local authorities, the proposed guidelines to visualise the advanced information on emissions and the zero-emission delivery and return options towards consumers.[1]

Develop recommendations and a toolset with and for local authorities to accelerate the adoption of zero-emission delivery and return options and choices.[1]

Integrate an intersectional analysis of consumers' gender, age, and socioeconomic status to account better for the customers' variety of expectations and motivations and develop solutions which cater for all social groups.[1]

Cooperation with the network of cities CIVITAS should be planned as appropriate.[1]

Nowhere on the page does the text discuss beneficiary or associated-partner legal status, grant-agreement signatory status, or any co-funding percentage for local authorities.[1]

Step 2 — Write the grounding instruction

Thinking out loud

The pattern from the lecture has four parts that all have to be present: name the exact source, forbid outside knowledge and common sense, forbid inference, and require an explicit 'not available' response for anything the text doesn't cover. A soft 'summarise using this text' request satisfies none of those four, which is exactly what let the colleague's draft invent details.

Using only the text of Horizon Europe call topic HORIZON-CL5-2023-D6-01-06 as published on CORDIS (https://cordis.europa.eu/programme/id/HORIZON_HORIZON-CL5-2023-D6-01-06), which I have pasted below, draft a short paragraph describing what the call requires from local authorities as partners.

Do not use any outside knowledge of Horizon Europe funding rules, general Work Programme conditions, consortium-composition conventions, or common-sense assumptions about how EU grants normally operate. Do not infer, extrapolate, or fill gaps with plausible-sounding detail that is not explicitly written in the pasted text — even if it would normally be true of Horizon Europe projects.

For every specific fact you state (a role, a percentage, a named methodology, a named organisation or network), you must be able to point to the exact sentence in the pasted text that supports it.

If the pasted text does not explicitly address something (e.g. the legal/beneficiary status of local authorities, co-funding percentages, or any other detail), you must write 'not available in the call text' for that point rather than guessing, generalising, or omitting it silently.

Step 3 — Check the colleague's draft clause by clause

With the source passages in hand, each factual claim in the colleague's draft was checked against them one at a time, the same discipline used to spot-check an extracted table row by row — here applied sentence by sentence to a drafted paragraph.[1]

Step 4 — Name the fabrication

The 10% municipal co-funding requirement is fabricated — it appears nowhere in the call text — and, together with the beneficiary/signatory claim, it is exactly what the grounding instruction's rule to write 'not available' when the text is silent would have blocked before it ever reached the manager's desk.[1]

Takeaways

  • A grounding instruction must do four things together: name the exact source, forbid outside knowledge and common sense, forbid inference, and require an explicit 'not available' response when the source is silent — a soft 'summarise using this text' request does none of these.
  • The instruction changes what the assistant is willing to output; it does not guarantee the assistant read the source correctly, so the drafted paragraph still needs the same clause-by-clause verification against the source as any other assistant output.
  • Verifying a drafted paragraph means checking every factual claim individually against the source and recording a supported/not-supported verdict, not just spot-checking the claims that look suspicious.
  • In this call text, the toolset, the intersectional consumer-behaviour analysis, and the CIVITAS cooperation were all genuinely supported; the beneficiary/signatory status and the 10% co-funding figure were both fabricated additions that a grounding instruction would have forced to 'not available'.
